## Long-running jobs
Applies to anything longer than a few minutes or anything measured: training, eval, benchmark, timing smoke, league.
- **Run it in a named tmux session, logging to a file.** `tmux new -d -s <name> '<cmd> 2>&1 | tee <log>'`. Never use a harness background shell for these; background shells are for short waits and polls only.
- **Refuse duplicates.** Before launch, check `pgrep -f '[m]y_job'` (PIDs; works on Linux and macOS) and `tmux ls`. If an instance is already running, don't start another. To see the command lines, use `pgrep -af` on Linux, `pgrep -lf` on macOS (there `-a` means "include ancestors"). The bracket stops pgrep from matching the agent's own `bash -c` wrapper, whose command line contains the pattern.
- **A dead wrapper isn't a dead job.** If a job seems to have died, check `pgrep` before relaunching. A killed or reaped wrapper shell can leave its children orphaned and still running. Relaunching on top of an orphaned 16-worker eval once froze the laptop.
- **Size workers by free RAM, not cores.** Check free memory (Linux: `free -g`; macOS: `memory_pressure` or `vm_stat`, total from `sysctl -n hw.memsize`) and budget per-worker memory.
- **Stop jobs precisely.** Use the job's STOP file, or `tmux send-keys -t <name> C-c` / SIGTERM to the session's process. Never use a `pkill -f` pattern broad enough to match unrelated processes; one agent killed its own shell that way.
- **Write run outputs to a persistent directory.** Results, logs, journals, telemetry and cross-check legs go in the project's results dir (or a dedicated data dir), never `/tmp`, `/dev/shm` or another tmpfs; those are for throwaways only. If the job writes to a scratch dir by default, pass an explicit persistent output path. A reboot once wiped a cross-check run's outputs because they sat in a temp dir, so its pre-registered criterion couldn't be fully checked. Temp dirs can be emptied at boot or by periodic cleanup on both Linux (systemd-tmpfiles) and macOS.
